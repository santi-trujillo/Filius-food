#### 1.1 Descripción del Negocio
FiliusFood es un negocio especializado en la venta de postres y sándwiches que necesita presencia digital para facilitar pedidos y mostrar su catálogo de productos.

#### 1.2 Objetivo del Proyecto
[Describe en 2-3 frases qué problema específico resuelve este sitio web]
Crear presencia digital para FiliusFood que elimine la necesidad de consulta 
física, permitiendo a los clientes ver el menú completo, visualizar productos, 
conocer ingredientes y precios antes de contactar por WhatsApp o visitar el 
establecimiento.


#### 1.3 Alcance
- **Incluye:** [Lista lo que SÍ abarcará el proyecto]

- **No Incluye:** [Lista lo que NO abarcará el proyecto en esta versión]

### 5. REQUERIMIENTOS NO FUNCIONALES

#### 5.1 Performance
- **RNF-01:** Tiempo de carga inicial < 3 segundos en 4G
- **RNF-02:** First Contentful Paint (FCP) < 1.8 segundos
- **RNF-03:** Imágenes optimizadas (WebP, tamaño máximo 200KB)
- **RNF-04:** CSS minificado < 50KB
- **RNF-05:** JavaScript minificado < 100KB

#### 5.2 Responsividad
- **RNF-06:** Diseño responsive desde 320px hasta 1920px
- **RNF-07:** Breakpoints: Mobile (320-767px), Tablet (768-1023px), Desktop (1024px+)
- **RNF-08:** Touch targets mínimo 44x44px en móvil

#### 5.3 Compatibilidad
- **RNF-09:** Chrome 90+, Firefox 88+, Safari 14+, Edge 90+
- **RNF-10:** iOS 13+ y Android 8+

#### 5.4 SEO
- **RNF-11:** Meta tags completos (title, description, og:image)
- **RNF-12:** Estructura HTML semántica (header, nav, main, section, footer)
- **RNF-13:** Alt text en todas las imágenes
- **RNF-14:** Schema.org markup para LocalBusiness y MenuItem
- **RNF-15:** Sitemap.xml y robots.txt

#### 5.5 Accesibilidad
- **RNF-16:** WCAG 2.1 Nivel AA
- **RNF-17:** Contraste de color mínimo 4.5:1
- **RNF-18:** Navegación por teclado funcional
- **RNF-19:** Screen reader compatible (ARIA labels)

#### 5.6 Seguridad
- **RNF-20:** HTTPS obligatorio
- **RNF-21:** Preparación para validación y sanitización de inputs (v2.0)
- **RNF-22:** Headers de seguridad (CSP, X-Frame-Options)

### 6. HISTORIAS DE USUARIO

#### HU-01: Visualizar Catálogo
**Como** cliente potencial  
**Quiero** ver el menú completo de postres y sándwiches con imágenes y precios  
**Para** decidir qué productos me interesan comprar  

**Criterios de Aceptación:**
- [ ] Ver mínimo 2 categorías (postres, sándwiches)
- [ ] Cada producto muestra: imagen, nombre, descripción breve, precio
- [ ] Imágenes cargan en menos de 2 segundos
- [ ] Grid responsive en móvil (1 columna) y desktop (3 columnas)

---

#### HU-02: Contactar por WhatsApp
**Como** cliente interesado  
**Quiero** contactar fácilmente a FiliusFood por WhatsApp  
**Para** hacer consultas o pedidos de forma directa  

**Criterios de Aceptación:**
- [ ] Botón flotante de WhatsApp visible en todas las secciones
- [ ] Click abre WhatsApp Web en desktop o app en móvil
- [ ] Mensaje predefinido: "Hola FiliusFood, vi su página web y me gustaría información sobre sus productos"
- [ ] Número de WhatsApp Business configurado y activo


---

#### HU-03: Navegación Móvil
**Como** usuario móvil  
**Quiero** navegar fácilmente por todas las secciones desde mi celular  
**Para** hacer pedidos de forma rápida sin complicaciones  

**Criterios de Aceptación:**
- [ ] Menú hamburguesa funcional en mobile
- [ ] Navegación entre secciones sin scroll perdido
- [ ] Botones y enlaces con tamaño táctil adecuado (min 44px)
- [ ] Sin zoom horizontal en ningún dispositivo

---

#### HU-04: Información de Contacto
**Como** visitante  
**Quiero** ver información de contacto, ubicación y horarios  
**Para** saber cómo comunicarme o visitar FiliusFood  

**Criterios de Aceptación:**
- [ ] Sección de contacto con: dirección, teléfono, email, redes sociales
- [ ] Horarios de atención visibles
- [ ] Enlaces a redes sociales funcionales

---

#### HU-05: Carga Rápida
**Como** usuario con conexión limitada  
**Quiero** que la página cargue rápido  
**Para** no perder tiempo esperando ni gastar muchos datos  

**Criterios de Aceptación:**
- [ ] Página interactiva en menos de 3 segundos en 4G
- [ ] Lazy loading en imágenes de productos

### 9. FLUJO DE DATOS

#### 9.1 Flujo Principal: Consultar y Contactar

1. Usuario ingresa al sitio → Carga inicial (HTML + CSS + JS)
2. Usuario navega por secciones → Smooth scroll sin recargar
3. Usuario visualiza catálogo → Lee products.json y renderiza
4. Usuario ve producto de interés → Decide contactar
5. Usuario hace click en botón WhatsApp → Abre WhatsApp
6. WhatsApp pre-rellena mensaje → Usuario envía consulta



#### 9.2 Gestión de Estado

- **Productos:** JSON estático cargado al inicio (products.json)
- **Navegación:** Estado en memoria para sección activa
- **Sin persistencia:** No se requiere LocalStorage ni cookies
